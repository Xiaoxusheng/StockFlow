> 版本：v1.0 ｜ 本文档是扫码领域（设备接入、解析、交互、业务场景）的唯一依据 ｜ 关联文档：[devices](devices.md)（设备生命周期/StockFlow Scan 应用/离线/监控）、[frontend](frontend.md)、[printing](printing.md)、[qr-code](qr-code.md)（SFQR 商品二维码协议唯一契约）、[inventory-rules](inventory-rules.md)、[business-flow](business-flow.md)

## 1. 定位与目标

**扫码枪不是附加功能，而是 StockFlow 仓储作业的核心输入设备之一。**

目标不是增加一个"扫码按钮"，而是让扫码枪真正参与以下业务：

```text
收货、上架、拣货、复核、打包、发货、盘点、移库、调拨、退货、质检
库存查询、库位查询、单据查询
```

形成标准扫码链路：

```text
扫码枪
 ↓
识别条码
 ↓
系统自动识别业务对象
 ↓
业务校验
 ↓
自动填充 / 自动执行
 ↓
成功反馈
 ↓
进入下一步
```

## 2. 设备接入层

### 2.1 接入方式

系统必须同时支持：

| 方式 | 说明 | 定位 |
|---|---|---|
| USB HID 扫码枪 | 模拟键盘输入（字符串 + Enter），PC 仓库工作站默认推荐方式 | **默认主方式** |
| 蓝牙 HID 扫码枪 | 同键盘输入方式工作，不要求用户安装额外驱动；Pad 端主要接入方式 | 支持 |
| 工业 PDA 内置扫描头 | Zebra / Honeywell / UROVO 等厂商扫描引擎，通过厂商 Adapter 接入（见 devices.md §5）；StockFlow Scan 独立应用承载 | **PDA 主方式** |
| USB / 串口扫码枪 | 浏览器端用 **Chrome Web Serial API** 实现 Serial/COM 接入（COM3、COM4、/dev/ttyUSB0 等作为输入来源）；桌面端代理模式为后备方案 | 架构预留 |
| 摄像头扫码 | 移动端/无枪场景补充，备用方式 | 辅助 |

### 2.2 Scanner Adapter 抽象（强制架构约束）

硬件逻辑禁止写死在业务页面中。前端必须建立统一适配层：

```text
Scanner Adapter
├── HIDScanner             USB/蓝牙 HID（PC + Pad）
├── SerialScanner          串口/COM（Web Serial API）
├── ZebraDataWedgeAdapter  Zebra DataWedge（工业 PDA）
├── HoneywellScannerAdapter Honeywell（工业 PDA）
├── UrovoScannerAdapter    UROVO（工业 PDA）
└── CameraScanner          摄像头
```

厂商适配器的生命周期管理、实体 Scan 键、设备注册与监控见 [devices.md](devices.md) §4–7。

**业务模块不能直接依赖 USB / COM / Keyboard Event，必须依赖 ScannerService。**

### 2.3 HID 键盘模拟扫码识别

针对 HID 扫码枪，不能简单监听 `keydown`，必须识别"极短时间内连续字符输入 + Enter"作为扫码事件，避免把人工键盘输入（如逐字输入 `SKU001`）误判为扫码。

事件模型：

```text
scanStart → scanBuffer → scanEnd
```

识别参数可配置：

```text
最小字符数（minLength）
最大字符数（maxLength）
最大输入间隔（字符间超时，ms）
结束字符（Enter / 自定义后缀）
```

### 2.4 部署模式

PC 仓库工作站典型结构：

```text
扫码枪
 ↓ USB
Windows / Linux
 ↓
浏览器（Chrome）
 ↓
StockFlow Web
```

不要求普通用户安装复杂驱动。

## 3. 前端 Scanner 架构

### 3.1 核心模块

```text
ScannerManager       设备管理、生命周期、状态
ScannerService       统一扫码入口（业务唯一依赖）
ScannerInputParser   HID 输入流解析（scanStart/Buffer/End）
ScannerEventBus      扫码事件分发
```

统一输出事件结构：

```ts
interface ScanResult {
  rawCode: string
  symbology?: string         // Code128 / QR / ...
  source: 'hid' | 'serial' | 'zebra' | 'honeywell' | 'urovo' | 'camera'
  timestamp: number
}
```

业务层不关心具体硬件品牌；设备与厂商 Adapter 的完整定义见 devices.md §4–5。

**约束**：业务页面禁止自己监听键盘，统一走 `ScannerManager → Scanner Event → 当前业务页面`。

**一期临时口径（作业效率提升层一期，2026-10-06；扫码作业优化同日收口）**：一期交付的 HID 扫码原语是
`components/scanner/ScanInput.tsx` + `hooks/useScanBuffer.ts`——**受控输入框内承接**：USB/蓝牙
HID 扫码枪（键盘模拟 + Enter）与手工键入都在组件自身受控 `<Input>` 焦点内完成缓冲解析
（`data-sf-scan-input` 标记并入 frontend.md §32 输入态抑制面：该焦点下页面级快捷键全部禁用）。
本口径与上述「业务页面禁止自己监听键盘」**不冲突**：被禁止的是各页面自行监听全局键盘、各自实现
扫码逻辑；`ScanInput` 是统一组件族的**唯一实现**，页面只消费组件、不碰键盘事件。完整
`ScannerManager → Scanner EventBus → 业务页面` 事件总线架构（含 serial/zebra/honeywell/urovo/camera
Source 与 `ScanField`/`ScanResult`/`ScanStatus`/`ScanHistory`/`ScanPreview` 全组件族、全局
`ScannerProvider` 单例）仍归 **F15/F16 立项**，一期不引入。既有
`ScanDirectCard`（components/device/ScanDirectCard.tsx，设备中心解析演示）保持不变。三模式
（normal/fast/continuous）与智能下一步档位口径见 §6.4、frontend.md §22：`autoAdvance: 'safe'`
仅允许查询/定位类低风险动作随连扫自动推进，确认收货/扣减类**必须显式按键**（禁止自动提交）。

**扫码作业优化（2026-10-06）**：三模式升级为**用户可切换偏好**——`stores/scan.ts` `useScanStore`
（localStorage `sf.scan.mode` 持久化）为唯一模式源，`ScanInput` 未传 `mode` prop 时内置
Segmented 切换器读写该 store（跨页面一致），显式传 `mode` 则页面受控并隐藏切换器；
新增 `hooks/useSmartScanNext.ts` 智能下一步——统一调 `POST /api/scanner/resolve` 识别后按
作业上下文（receive/quality/putaway/count/stockmove/transfer/inventory/global）映射为
locate-task / locate-item / locate-bin / navigate 指令，页面执行「继续」步（单号前缀→作业页
冻结路由表见该文件 `DOC_KIND_ROUTES`）。Pad 侧扫→判→继续收口：`PadActionBar` 扫码弹窗统一
托管 `ScanInput`（未传 `onScanSubmit` 时走 global 智能路由），收货/质检/库存页弹窗扫码后
保持打开可连扫；原 `PadScanStub` 占位原语全员下线删除（pad.css `.sf-pad-scan-stub` 样式随之移除）。
盘点（盘盈亏）、移库等高风险/库存变动动作仍一律显式按键提交，扫码仅承担定位。

### 3.2 扫码组件族

前端基于 **React + Ant Design**（技术栈见 architecture.md §11.3）封装统一组件，通过全局 `ScannerProvider`（React Context）挂载 ScannerService；业务页面直接使用组件，禁止每个页面重新实现扫码逻辑：

```text
<ScanInput />     扫码输入框
<ScanField />     表单扫码字段
<ScanResult />    扫码结果展示
<ScanStatus />    扫码状态指示
<ScanHistory />   最近扫码记录
<ScanPreview />   扫码预览确认
```

使用示例：

```vue
<ScanInput
  placeholder="扫描 SKU / 条码"
  auto-focus
  :continuous="true"
  @scan="handleScan"
/>
```

### 3.3 ScanInput 能力清单

至少支持以下属性：

```text
autoFocus        自动聚焦
continuous       连续扫码模式
suffix / prefix  前后缀处理
minLength / maxLength  长度约束
debounce         防抖
sound            声音反馈开关
vibration        震动反馈开关
manualInput      允许手工输入兜底
clearAfterScan   扫码后清空输入框
```

### 4.7 故障处理与手工输入兜底

1. 扫码枪断开时页面不能卡死：提示"扫码枪不可用"，仍可**手工输入条码**继续作业；恢复连接后自动恢复扫码能力。
2. 所有扫码输入框必须同时允许扫码枪与键盘手工输入，但**手工输入必须经过同样的业务校验**——不能因为是手工输入就绕过权限、库存、状态、批次、序列号检查。
3. 无扫码枪环境下系统必须可以运行：键盘输入、摄像头扫码、手动选择；但仓库 PC 工作站场景以 USB HID 扫码枪为主要交互方式。

## 5. 统一条码解析

### 5.1 支持码制

至少支持：

```text
Code128、Code39、EAN-13、EAN-8、UPC
QR Code、DataMatrix
```

业务层不强制要求所有条码为同一种（打印与解析端均需覆盖，见 printing.md §4）。

### 5.2 BarcodeResolver 统一解析

扫描结果必须经过统一解析：

```text
原始条码 → BarcodeResolver → 识别类型 → 查询对象
```

**第 0 段：SFQR 商品二维码分支（2026-10-05 新增，优先级最高）**。扫描内容以 `SFQR|` 前缀自标识即锁定类型，先于单号前缀与全部条码匹配器执行（协议唯一契约见 [qr-code.md](qr-code.md)）：

```text
SFQR|1|SKU|<sku_code>  → SKU（载荷 = SKU 编码）
```

- `HasPrefix("SFQR|")` 即锁型 → 协议解析 → 按载荷查 SKU；格式/版本/类型错误显式返回 `SFQR_INVALID` / `SFQR_VERSION_UNSUPPORTED` / `SFQR_TYPE_UNSUPPORTED`，**失败不落回**后续匹配器（禁止把残缺 SFQR 当普通条码静默处理）。
- 载荷合法但 SKU 不存在/软删/停用 → `SKU_NOT_FOUND`（与 SKU 条码分支同口径）。
- 同一字符串即使被注册为 SKU 条码也走 SFQR 分支（`SFQR|` 为协议保留命名空间，条码注册侧已拒绝该前缀，见 qr-code.md §3.2）。
- type=BIN/BOX/PALLET 为协议预留未实现，显式返回 `SFQR_TYPE_UNSUPPORTED`。

识别映射（第 1 段起，顺序冻结）：

```text
单号前缀      → 各域单据/任务（前缀命中即锁型，不落回）
SKU 条码      → SKU
库位条码      → Bin
箱码          → Package/Box
托盘码        → Pallet
入库单号      → Inbound
出库单号      → Outbound
拣货任务码    → PickTask
盘点任务码    → CountTask
序列号        → SerialNumber
批次码        → Batch
```

### 5.3 后端解析 API

提供统一解析接口：

```text
POST /api/scanner/resolve
请求：{ "code": "SKU001234" }
响应：{ "type": "sku", "id": "xxx", "code": "SKU001234", "name": "xxx" }
```

SFQR 商品二维码走同一端点（前端零自研解析）：

```text
请求：{ "code": "SFQR|1|SKU|SKU-001" }
响应：{ "type": "sku", "id": "42", "code": "SKU-001", "name": "商品名" }
```

**响应实现超集（2026-10-05 依实现回写）**：

- 多命中：库位码/批次码等跨对象命中时响应携带 `items` 全量列表由前端选择，顶层 `id=0` 表示未定位（如 `{type, id:0, code, name, items:[...]}`）。
- 去重注记：响应恒含 `duplicate` 布尔字段（scanner.md §6.6 去重窗口标记，不抑制识别、scan_logs 照常落库）。
- 错误响应为统一信封业务错误码（§6.1），SFQR_* 与 NOT_FOUND 类均先落 scan_logs 审计再返回。

**硬性约束**：不能把所有业务逻辑塞进 resolve API。解析与业务执行必须分离：

```text
resolve barcode（识别对象）  +  execute receiving（执行业务）
```

业务执行走各自领域的业务 API（收货/上架/拣货/…），确保事务、权限、状态机、库存校验都在业务 API 中完成。

## 6. 扫码交互规范

### 6.1 扫码错误反馈

扫码错误必须快速反馈，错误码至少包括：

```text
UNKNOWN_BARCODE        无法识别的条码
SKU_NOT_FOUND          SKU 不存在
BIN_NOT_FOUND          库位不存在
ORDER_NOT_FOUND        单据不存在
TASK_NOT_FOUND         任务不存在
SKU_MISMATCH           商品不匹配
BIN_MISMATCH           库位不匹配
BATCH_MISMATCH         批次不匹配
SERIAL_INVALID         序列号无效
SERIAL_USED            序列号已使用/已出库
INVENTORY_NOT_ENOUGH   库存不足
TASK_COMPLETED         任务已完成
ORDER_COMPLETED        单据已完成
```

SFQR 商品二维码分支错误码（2026-10-05 新增，识别类 13→16；格式/触发条件唯一依据见 [qr-code.md §5](qr-code.md)）：

```text
SFQR_INVALID             SFQR 载荷格式非法（段数错误/载荷空/超 64 字符）
SFQR_VERSION_UNSUPPORTED SFQR 协议版本不支持（version ≠ 1，明确拒绝不降级）
SFQR_TYPE_UNSUPPORTED    SFQR 类型已预留未实现（BIN/BOX/PALLET 及未知类型）
```

**前端禁止只显示"操作失败"**，必须说明四要素：

```text
错误原因（对应错误码的中文说明）
当前对象（当前任务/单据/库位状态）
应该扫描什么（期望对象）
下一步怎么办
```

### 6.2 声音 / 震动 / 视觉反馈

仓库环境必须支持声音反馈：

```text
成功 → 短提示音
错误 → 明显错误音
```

系统设置中可启用/关闭声音。

视觉反馈：

```text
绿色 = 成功
红色 = 错误
黄色 = 警告
```

**颜色不能成为唯一反馈方式**（必须同时有文字/图标说明）。

移动设备支持震动时：

```text
成功 → 短震
错误 → 长震
```

PC USB 扫码枪不强行依赖震动。

### 6.3 扫码自动聚焦

```text
进入高频扫码页面 → 自动聚焦扫码输入
操作成功后 → 自动重新聚焦
```

确保员工可以连续扫码、连续作业，不需要鼠标点击输入框。

### 6.4 扫码模式（三种）

| 模式 | 行为 | 适用 |
|---|---|---|
| 普通模式 | 扫码 → 填充 → 人工确认 | 表单填写类 |
| 快速模式 | 扫码 → 自动确认 → 下一项 | 中风险、逐项作业 |
| 连续模式 | 连续扫码 → 自动累计 → 自动完成 | 数量累计类作业 |

**根据业务危险程度决定是否允许自动确认**：库存变更、高风险动作不能无条件自动执行。

**前端落地（扫码作业优化，2026-10-06）**：三模式为用户可切换偏好（`useScanStore` 持久化，
`ScanInput` 内置切换器），模式只影响输入节奏与推进幅度（`useScanBuffer` 判定 viaGun /
fastRhythm / repeatCount），**不改变风险分级**——自动推进仅在页面声明 `autoAdvance: 'safe'`
（纯查询/定位）时发生；确认收货 / 上架执行 / 质检判定 / 登记实盘（盘盈亏）/ 完成移库等
一切业务提交永远显式按键。连续模式的「自动完成」指同码累计计数与定位类动作自动推进，
不含业务提交。

### 6.5 风险分级确认规则

| 风险 | 业务 | 确认规则 |
|---|---|---|
| 低风险 | 库存查询、库位查询、SKU 查询 | 扫码 → 自动打开 |
| 中风险 | 收货、盘点、拣货 | 扫码 → 自动匹配 → 数量确认 |
| 高风险 | 出库完成、发货、库存调整、报损 | 扫码 → 校验 → **明确确认** → 执行业务 |

### 6.6 扫码幂等

扫码设备可能因配置问题重复发送（如 `SKU001 Enter` 连续两次）。必须区分"正常连续扫码"与"重复事件"：

- 极短时间内完全相同的事件（同码 + 同页面 + 同任务上下文）按重复事件去重，不产生重复业务。
- 正常连续扫码（如同 SKU 连续扫 10 次计数收货）允许重复，用于数量累计。
- 具体幂等规则按业务定义（收货计数 vs 出库执行），与后端幂等体系（architecture.md §3）协同。

### 6.7 扫码与库存安全（硬性约束）

扫码不能绕过库存规则：

```text
扫描 SKU 识别成功，但库存不足 → 仍然不能出库
扫描正确商品 + 错误库位       → 必须阻止
扫描已出库的 SN               → 必须阻止
```

一切库存校验、锁定、流水、状态机检查与手工操作完全一致。

### 6.8 扫码作业页面 UI

扫码页面必须明显区别于普通后台列表，设计目标：

```text
快速、稳定、高信息密度、低输入、少点击、强反馈
```

页面重点突出：当前任务、当前库位、当前 SKU、要求数量、已完成数量、扫描状态。

示例（拣货）：

```text
┌───────────────────────────┐
```

## 7. 业务场景深度接入

> 通用规则：每个场景都遵循 §1 标准链路；错误反馈遵循 §6.1；风险分级遵循 §6.5；库存安全遵循 §6.7。优先级见 §10。

### 7.1 采购收货扫码（第一优先级）

收货页面流程：

```text
打开收货任务
→ 扫描采购单 → 自动加载订单
→ 扫描商品 → 识别 SKU → 自动定位订单明细
→ 数量确认 → 批次 → 效期 → 收货
```

**连续扫码计数**：同一 SKU 连续扫描 10 次，数量自动 1→2→…→10，禁止要求工作人员每次手工输入"数量=1"。

**箱码收货**：支持扫描箱码（如 `BOX202610020001`），显示箱号、供应商、采购单、SKU、数量、批次，实现整箱级收货。

### 7.2 质检扫码（第二优先级）

```text
扫描收货单 → 自动进入质检
扫描 SKU   → 自动定位明细
扫描批次   → 自动确认批次
```

序列号商品：扫描序列号 → 自动加入待检列表。

### 7.3 上架扫码（第一优先级）

流程：

```text
扫描上架任务 → 扫描商品 → 扫描库位 → 系统校验 → 确认数量 → 上架完成
```

必须校验：

```text
商品是否正确
库位是否正确
库位是否允许存放
库位容量是否足够
批次是否匹配
```

错误示例：扫描商品 A 但任务要求商品 B → 红色错误状态，"商品不匹配，请扫描指定商品"。
扫描正确 → 成功反馈 → 自动进入下一项。

### 7.4 库位扫码（通用能力）

所有库位必须支持二维码/条码（如 `A-01-03-05`）。扫描库位码后进入库位详情，显示：

```text
仓库、库区、货架、库位、容量、当前库存、SKU、批次、效期
```

### 7.5 拣货扫码（第一优先级）

拣货页面必须**扫码优先**：

```text
扫描拣货任务
→ 扫描库位 → 系统检查是否正确库位
→ 扫描商品 → 系统检查是否正确 SKU
→ 确认数量 → 完成
```

库位校验示例：应该去 `A-01-03-05`，员工扫描 `A-01-03-06` → 禁止继续，显示正确库位。

**连续拣货**：扫描库位 → 扫描商品 → 数量累计 → 完成 → 自动跳下一任务；避免每件商品都要鼠标点击"确认→下一步→确认"。

**序列号拣货**：扫描 SKU → 扫描 SN → 校验 SN 属于该 SKU、处于可出库状态 → 加入订单。序列号不存在/已出库/已退货/不属于当前 SKU/被冻结 → 必须立即阻止。

### 7.6 复核扫码（第一优先级）

复核环节必须支持连续扫描商品条码：

```text
扫描出库单 → 扫描商品 → 自动匹配出库明细 → 数量累计
→ 全部匹配 → 复核完成
```

识别并标记：正确、少货、多货、错货。扫到错误商品 → `❌ 商品不属于当前订单`，禁止继续。

**序列号复核**：扫描 SN → 验证订单、SKU、状态、库存 → 复核成功。确保出库序列号与系统实际库存一致。

### 7.7 打包扫码（第二优先级）

```text
扫描出库单 → 自动打开待打包订单
→ 扫描商品 → 自动确认包裹内容
→ 全部商品匹配 → 允许完成打包
```

支持创建包裹、多个包裹、包裹编号、箱码。

**箱码绑定**：扫描箱码 `BOX001`，连续扫描商品 `SKU001/SKU002/SKU003`，系统建立箱码→商品绑定，最终形成 `箱码 → 包裹 → 出库单 → 客户` 链路。

### 7.8 发货扫码（第二优先级）

发货区扫描包裹码，自动显示：

```text
订单、客户、仓库、包裹、物流、重量、状态
```

确认发货后：

```text
包裹状态 = 已发货
订单状态 = 已发货
```

并记录：发货时间、发货人、扫描设备、扫码时间。

### 7.9 盘点扫码（第一优先级）

```text
扫描盘点任务 → 扫描库位 → 读取系统库存
→ 扫描商品 → 自动记录实盘数量
```

同一商品连续扫描：第一次→1、第二次→2、第三次→3。支持手动修改，但**手动修改必须填写原因**。

**批量扫码盘点**：扫描一个库位后连续扫描多个 SKU：

```text
A-01-03-05 下扫描：
SKU001、SKU001、SKU002、SKU003、SKU003、SKU003
自动统计：SKU001=2、SKU002=1、SKU003=3
→ 与系统库存比较 → 生成差异
```

### 7.10 移库扫码（第一优先级）

```text
扫描移库任务 → 扫描原库位 → 扫描商品 → 确认数量
→ 扫描目标库位 → 系统校验 → 完成移库
```

错误目标库位不能继续。

### 7.11 调拨扫码（第二优先级）

调拨出库：

```text
扫描调拨单 → 扫描商品 → 扫描批次/SN → 确认数量
```

调拨入库：

```text
扫描调拨单 → 扫描运输箱 → 扫描商品 → 确认数量 → 完成入库
```

### 7.12 退货扫码（第二优先级）

销售退货：

```text
扫描退货单 → 扫描商品 → 扫描 SKU/SN/批次 → 确认数量 → 质检
```

系统自动显示原订单、原出库记录、原序列号、原批次，用于追溯。

### 7.13 扫码查库存 / 库位 / 序列号（第三优先级）

高频功能**扫码查库存**：

| 扫描对象 | 立即显示 |
|---|---|
| SKU | 商品、SKU、总库存、可用库存、锁定库存、仓库分布、库位分布、批次、效期 |
| 库位 | 该库位所有 SKU、库存数量、批次、效期 |
| 序列号 | SKU、当前状态、当前库位、入库记录、调拨记录、出库记录 |

### 7.14 扫码追溯（第三优先级）

增加**扫码追溯**入口：扫描 SKU / 批次 / SN / 箱码 / 托盘码 / 单据码，自动进入对应追溯页面（追溯链路定义见 inventory-rules.md §10）。

### 7.15 托盘管理（第三优先级）

增加基础托盘能力：

```text
托盘字段：托盘编号、托盘码、仓库、当前库位、状态
```

支持扫描托盘 → 查看托盘内容。一个托盘可绑定多个箱、多个 SKU、多个批次。

### 7.16 箱码管理（第三优先级）

增加**箱码中心**：

```text
生成箱码、查询箱码、打印箱码
绑定商品、绑定订单、绑定包裹
拆箱、合箱、箱码追溯
```

## 9. 最终仓库作业流（角色视角）

| 角色 | 扫码作业流 |
|---|---|
| 收货员 | 扫描采购单 → 扫描商品 → 连续扫码自动累计数量 → 扫描批次 → 完成收货 |
| 上架员 | 扫描上架任务 → 扫描商品 → 扫描库位 → 系统验证 → 完成上架 |
| 拣货员 | 扫描拣货任务 → 扫描库位 → 扫描商品 → 连续拣货 → 自动进入下一任务 |
| 复核员 | 扫描出库单 → 连续扫描商品 → 系统实时核验 → 全部匹配 → 复核完成 |
| 打包员 | 扫描订单 → 扫描商品 → 扫描箱码 → 建立包裹 → 打印箱码/面单 |
| 发货员 | 扫描包裹码 → 自动显示订单 → 核对 → 确认发货 → 打印发货凭证 |
| 盘点员 | 扫描盘点任务 → 扫描库位 → 连续扫描商品 → 自动累计 → 系统库存 vs 实盘 → 生成差异 |

## 11. 验收标准

最终必须现场模拟以下环境完成验收：

```text
一把 USB 扫码枪 + Windows PC + Chrome + StockFlow
```

现场走通业务：

```text
采购收货、入库、上架、库存查询、拣货、复核
打包、发货、盘点、移库、调拨、退货、序列号追溯
```

验收检查项：

```text
✓ 不依赖鼠标进行高频扫码操作
✓ 扫错商品可以立即发现
✓ 扫错库位可以立即发现
✓ 扫错单据可以立即发现
✓ 重复扫码不会造成重复业务
✓ 库存不足不能强行出库
✓ 库存变化有流水
✓ 操作有日志
✓ 扫码设备异常可以手工操作
✓ 扫码成功有明确反馈
✓ 扫码失败有明确原因
```
