# StockFlow 业务流程与单据规范

> 版本：v1.0 ｜ 本文档是业务流程实现的唯一依据 ｜ 关联文档：[inventory-rules](inventory-rules.md)、[requirements](requirements.md)、[scanner](scanner.md)（各业务环节的扫码作业规范）

---

## 1. 基础资料

### 1.1 商品管理

字段要求：

```text
商品编号、商品名称、商品简称、分类、品牌、型号、规格、单位
重量、长、宽、高、体积、图片、描述、状态、备注
```

### 1.2 SKU 管理

字段要求：

```text
SKU 编码、商品编码、商品名称、条码、规格属性
成本价、参考售价、安全库存、最大库存、最小补货数量
是否批次管理、是否效期管理、是否序列号管理、是否启用
```

SKU 的批次/效期/序列号开关直接决定该 SKU 在入库、库存、出库环节的业务分支。

### 1.3 商品图片

支持：上传、预览、删除、主图、多图片、附件。

### 1.4 供应商

支持完整 CRUD 及：联系人、电话、邮箱、地址、商品关系、历史采购、到货情况、供应商状态、备注。

**业务规则**：不能删除已经产生业务记录的供应商，应使用停用。

### 1.5 客户

支持：客户编码、客户名称、联系人、电话、地址、邮箱、收货地址、历史订单、历史出库、状态。

### 1.6 仓库空间结构

完整四级结构：

```text
仓库 → 库区 → 货架 → 库位
```

| 层级 | 字段 |
|---|---|
| 仓库 | 编码、名称、地址、联系人、电话、面积、容量、类型、状态、负责人 |
| 库区 | 编码、名称、所属仓库、类型、容量、状态 |
| 货架 | 编码、所属库区、层、列、容量、状态 |
| 库位 | 库位编码、仓库、库区、货架、层、列、最大容量、当前容量、状态、库位类型 |

## 2. 采购管理

### 2.1 流程

```text
采购申请 → 采购订单 → 审核 → 到货 → 收货 → 质检 → 上架 → 入库完成
```

### 2.2 采购订单状态

```text
草稿 → 待审核 → 已审核 → 部分到货 → 到货完成 → 已完成
                                                    ↘ 已取消
```

### 2.3 数量约束（防止超量收货）

采购订单明细必须保留四个数量字段，收货时后端强校验：

```text
原始数量 ≥ 已到货数量 + 待到货数量
拒收数量 单独记录
累计收货数量（含合格 + 不合格待定）不得超过 原始数量
```

---

## 3. 入库管理

### 3.1 入库类型

```text
采购入库、生产入库、销售退货入库、调拨入库、其他入库
```

### 3.2 完整流程

```text
入库单 → 收货 → 验收 → 质检 → 上架任务 → 上架 → 库存增加 → 库存流水 → 操作日志
```

### 3.3 部分收货

入库单支持部分收货：每次收货记录本次数量，剩余数量继续跟踪，直到全部收齐或关闭。

### 3.4 异常收货

支持登记以下异常类型：

```text
少货、多货、错货、破损、包装异常、批次异常、效期异常
```

异常必须支持拍照、上传附件，并自动进入异常中心（见 §11）。

---

## 4. 质检

### 4.1 检验方式

```text
免检、抽检、全检
```

### 4.2 质检记录字段

```text
检验数量、合格数量、不合格数量、检验结果
检验人、检验时间、原因、图片、附件
```

### 4.3 处理结果

```text
合格、部分合格、不合格、退供应商、报废、返工、降级、转不良品仓、特批放行
```

不合格品转不良品仓时，必须产生对应的库存变动与流水（不良品库存状态，见 inventory-rules）。

---

## 5. 上架

### 5.1 上架任务状态

```text
待上架 → 上架中 → 已完成
```

### 5.2 上架操作要求

支持：

```text
推荐库位、手动指定库位、扫码库位、扫码商品
数量确认、批次确认、效期确认、异常上报
```

### 5.3 推荐库位算法依据

推荐库位必须综合考虑：

```text
库位剩余容量
商品已有存放位置（优先同 SKU 集中存放）
库区类型
批次要求
商品属性（重量/体积/温区等）
拣货需求（高频拣货商品靠近出货口）
```

---

## 6. 销售管理

### 6.1 销售订单字段

```text
客户、商品、数量、单价、金额、仓库、收货地址、配送方式、备注
```

### 6.2 流程

```text
订单 → 审核 → 库存预占 → 出库
```

审核通过即触发库存预占（锁定库存，见 inventory-rules §4），预占失败则订单无法进入出库流程。

---

## 7. 出库管理

### 7.1 出库类型

```text
销售出库、生产领料、调拨出库、其他出库、报损出库
```

### 7.2 完整流程

```text
销售订单 → 库存分配 → 拣货 → 复核 → 打包 → 发货 → 库存正式扣减
```

注意：库存预占发生在审核时，**库存正式扣减发生在发货完成时**，中间全部通过锁定库存保证一致性。

---

## 8. 出库执行细节

### 8.1 库存分配

支持策略：

```text
FIFO（先入先出）
FEFO（先到期先出）
指定批次
指定仓库
指定库位
```

分配结果必须向用户展示分配理由：

```text
为什么分配这个库位？（库位选择依据）
为什么使用这个批次？（批次策略命中原因）
当前库存是否满足？（可用库存 vs 需求数量）
```

### 8.2 拣货

拣货模式：

```text
单订单拣货、批量拣货、波次拣货、分区拣货
```

拣货任务内容：

```text
拣货单 → SKU → 来源库位 → 数量 → 操作人 → 完成时间
```

拣货过程支持：扫码校验、缺货上报、少货上报、库位异常上报、替代处理（换库位/换批次）。

### 8.3 复核

复核必须重新确认：

```text
SKU、条码、数量、批次、序列号、订单
```

复核识别的异常类型：

```text
错货、少货、多货、批次错误、序列号错误
```

### 8.4 打包

打包记录字段：

```text
包裹编号、包装材料、长、宽、高、重量、体积、快递公司、快递单号
```

**一个订单允许多个包裹**，包裹与订单明细为多对多关系（拆包场景）。

### 8.5 发货

发货信息：

```text
发货单号、物流公司、物流单号、发货仓、发货时间、发货人、包裹数量
```

发货状态：

```text
待发货 → 已发货 → 运输中 → 已签收
                    ↘ 异常
```

发货完成是库存正式扣减的触发点（事务边界，见 architecture.md §4）。

---

## 9. 退货

### 9.1 销售退货

```text
退货申请 → 审核 → 收货 → 质检 → 正常库存 / 不良品
```

质检结果决定退货入库去向：合格入正常库存，不合格入不良品库存。

### 9.2 采购退货

```text
退货申请 → 审核 → 退货出库 → 供应商
```

采购退货走出库流程，扣减对应库存并保留完整流水。

---

## 10. 调拨与盘点

### 10.1 调拨

支持两种维度：

```text
仓库 → 仓库
库位 → 库位
```

调拨单状态机：

```text
草稿 → 待审核 → 待出库 → 调拨中 → 待入库 → 已完成
                                              （任一环节可）已取消
```

库存约束：源仓减少、目标仓增加，两端都必须生成库存流水。跨仓调拨在途数量通过"在途库存"体现。

### 10.2 盘点

盘点范围支持：

```text
全盘、按仓、按库区、按货架、按库位、按 SKU
周期盘点、动碰盘点、抽盘
```

盘点流程：

```text
创建盘点 → 冻结范围（范围内库位/库存锁定）→ 实盘 → 系统对比生成差异
→ 差异审核 → 调整（生成库存调整单）→ 库存流水
```

**硬性规则**：禁止用户直接修改系统库存来"解决盘点差异"，差异必须走库存调整单 + 审批链路。

---

## 11. 库存调整与异常中心

### 11.1 库存调整

所有库存调整必须走：

```text
申请（必须填原因）→ 审核 → 执行 → 生成库存流水
```

调整类型：盘盈、盘亏、损耗、报废、其他调整。

### 11.2 异常中心

统一处理九类异常：

```text
收货异常、质检异常、上架异常、库存异常
拣货异常、复核异常、物流异常、盘点异常、系统异常
```

异常生命周期：

```text
发现 → 创建 → 分派 → 处理中 → 待复核 → 已解决 → 已关闭
```

异常单支持：图片、附件、评论、处理人、责任人、处理记录。

---

## 12. 审批

### 12.1 必须审批的业务

```text
库存调整、库存报损、盘亏、盘盈
采购、销售、调拨、退货
```

### 12.2 审批流

```text
提交 → 待审核 → 通过 / 驳回
```

审批必须记录：审批人、审批时间、审批意见、审批结果。审批记录属于审计数据，不可修改删除（见 database.md §7）。

## 13. 单据规范（全系统统一）

### 13.1 单据编号规则

统一编号规则引擎，示例格式：

```text
PO-20261002-000001   采购单
IN-20261002-000001   入库单
OUT-20261002-000001  出库单
TR-20261002-000001   调拨单
CK-20261002-000001   盘点单
QC-20261002-000001   质检单
```

支持配置：前缀、日期段、流水号、仓库编码段。

**禁止**简单使用数据库自增 ID 当业务单号。

### 13.2 单据状态机

每一种业务单据必须有明确的状态机，例如：

```text
草稿 → 待审核 → 已审核 → 处理中 → 已完成
```

**硬性规则**：

- 禁止直接 `UPDATE ... SET status = 'completed'` 跳状态。
- 所有状态变化必须经过业务方法（状态机守卫），校验当前状态允许的迁移目标。
- 每次状态变化记录：变化前状态、变化后状态、操作者、时间、原因。

### 13.3 单据作废与生命周期

业务数据原则上不能物理删除。支持：作废、取消、关闭、归档、停用。

**已影响库存的单据不能直接删除**，只能通过反向业务单据冲正。

### 13.4 业务时间字段

单据不能只保存 created_at，必须按业务保存各环节时间，用于效率分析：

```text
创建时间、审核时间、收货时间、质检时间、上架时间
拣货时间、复核时间、打包时间、发货时间、完成时间
```

## 14. 全局业务原则（WMS 与 CRUD 的区别）

以下真实业务场景必须在设计阶段覆盖：

```text
部分收货    部分发货    部分退货    部分质检
部分上架    部分拣货    部分复核    部分打包
订单拆包    多个包裹    多仓库存    多库位库存
多批次库存  序列号库存  库存锁定    库存冻结
库存不足    重复提交    并发操作    异常处理
审核        撤销        作废        历史追溯
```

任何"整单一次性完成、不支持中间态"的设计都不符合本规范。
