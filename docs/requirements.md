## 1. 项目概述

| 项 | 内容 |
|---|---|
| 项目名称 | StockFlow |
| 中文名称 | 库流智能仓储管理系统 |
| 英文名称 | StockFlow Intelligent Warehouse Management System |
| 项目类型 | 生产级 WMS（仓储管理系统） |
| 系统文字 | 界面以中文为主，代码与接口使用英文 |

### 1.1 最高优先级目标

系统必须围绕完整业务闭环构建：

```text
基础资料 → 采购/销售业务 → 入库/收货/质检/上架 → 库存 → 调拨 → 盘点
→ 出库/拣货/复核/打包/发货 → 退货 → 追溯 → 报表 → 审计
```

明确不做以下"毕业设计后台模板"形态：

- 商品 CRUD、入库 CRUD、出库 CRUD、库存 CRUD、几个 Dashboard 卡片。

### 1.2 生产级要求

整个项目必须遵守：真实业务优先、数据正确优先、库存一致性优先、安全优先、可维护性优先、可扩展性优先、用户体验优先。

每个业务功能设计时必须回答（评审清单）：

```text
谁操作？什么时候操作？对什么数据操作？
操作前是什么？操作后是什么？
是否需要审核？是否影响库存？是否生成流水？
是否需要日志？失败如何恢复？重复提交怎么办？
```

## 2. 功能需求总览

### 2.1 Dashboard（首页）

Dashboard 必须根据角色展示不同内容，不是简单的四个数字卡片。

**管理层视图**：

```text
仓库总数、SKU 总数、总库存、库存金额
今日入库、今日出库、订单数量
库存预警、临期商品、积压商品
待审核单据、待处理异常
```

**仓库人员视图**：

```text
待收货、待上架、待拣货、待复核
待打包、待发货、待盘点、待处理异常
```

**图表**（至少支持）：

- 入库趋势、出库趋势、库存趋势、库存金额趋势
- 仓库库存分布、SKU TOP、库存预警、积压库存
- 订单状态、仓库效率

所有图表支持时间维度切换：`7天 / 30天 / 90天 / 自定义时间`。

Dashboard 数据必须来自真实业务数据（API → Service → Database），禁止写死。

### 2.2 我的工作台

为仓库操作人员建立**我的工作台**：

```text
我的待办、我的任务、我的异常
我的最近操作、今日完成数量、今日效率
```

目标：仓库人员打开系统后不用到处找任务。

### 2.3 通知中心

```text
通知类型：系统通知、审批通知、库存预警、效期预警、异常通知、任务通知
状态管理：未读 / 已读 / 全部已读
```

### 2.4 报表中心

至少包含以下报表：

```text
库存报表、库存流水报表、入库报表、出库报表
采购报表、销售报表、调拨报表、盘点报表、质检报表
库存金额、库存周转、库存积压、ABC 分析
仓库效率、人员效率
```

每张报表支持：筛选、排序、分页、导出 Excel、打印、时间范围。

**报表打印规范**：打印页面必须独立于普通列表，包含：

```text
页眉：公司名称、报表名称、统计日期
表体：业务字段（如 库存报表：仓库/SKU/商品名称/库位/批次/库存/可用库存/锁定库存）+ 合计
页脚：制表人、审核人、打印时间
```

### 2.5 库存智能能力（增强模块）

| 能力 | 依据 | 输出 |
|---|---|---|
| 智能补货 | 历史销量、当前库存、安全库存、采购周期、最近出库量 | 建议补货数量 |
| 库存预测 | 历史数据 | 未来 7 天 / 30 天库存变化预测 |
| 库位推荐 | 容量、SKU 属性、已有库位、批次、拣货需求 | 推荐上架库位 |
| 积压识别 | 最近移动时间 | 30/60/90 天未动库存 |

### 2.6 仓库可视化

提供仓库平面可视化，可逐层查看：`仓库 → 库区 → 库位 → 当前库存`。

库位状态显示：`空闲 / 部分占用 / 满载 / 锁定 / 冻结 / 异常`。

点击库位打开详情：SKU、库存、批次、效期、序列号、入库日期、最近移动、最近操作人。

### 2.7 统一搜索

支持统一搜索：SKU、商品名称、条码、单据号、批次、序列号、客户、供应商、库位、物流单号。

高频页面需要：快捷搜索、高级筛选、保存筛选条件。

### 2.8 批量操作

核心列表支持：批量审核、批量作废、批量打印、批量导出、批量分配、批量分派任务、批量启用、批量停用。

批量操作必须有：数量提示、二次确认、执行结果、失败列表。

### 2.9 商品二维码（SFQR，2026-10-05 新增）

围绕商品/SKU 提供协议化二维码能力（协议唯一契约见 [qr-code.md](qr-code.md)），四项核心需求：

```text
生成     QR 由 SKU 身份 + SFQR 协议动态生成（SFQR|1|SKU|<sku_code>），不持久化、
         不新增二维码存储；前端构造唯一点，禁止第二处拼串。
预览     二维码中心页面（基础资料组「商品二维码」）+ SKU 列表「二维码」入口：
         预览、载荷明文、详情抽屉；扫码识别后直达该页面。
批量打印 统一走打印任务（模板 → PrintTask → 预览 → 执行），批量前不可打印校验
         （停用 SKU 拒绝并逐条列出）；历史重打 = 新任务不碰历史，缺行身份快照
         data_id 的旧任务 fail-closed 不可自动重打。
扫码识别 扫码枪扫入 SFQR 经统一解析接口识别（未知版本/类型明确报不支持，禁止
         静默解析失败），直达二维码中心。
```

权限：复用既有权限点（页面 `sku:view`、打印 `printing:task:create`、模板 `printing:template:list`、扫码 `scanner:resolve:list`），不新增 qr:* 权限码。

## 3. 业务模块需求摘要

详细业务流程见 [business-flow.md](business-flow.md)，库存规则见 [inventory-rules.md](inventory-rules.md)。

| 模块 | 核心要求 |
|---|---|
| 基础资料 | 商品（编号/名称/分类/品牌/规格/单位/重量/尺寸/图片等）、SKU（条码/规格属性/成本价/安全库存/批次/效期/序列号开关等）、分类、单位、供应商、客户 |
| 仓库空间 | 仓库 → 库区 → 货架 → 库位 四级结构，完整属性与状态管理 |
| 采购管理 | 采购申请 → 采购订单 → 审核 → 到货 → 收货 → 质检 → 上架 → 入库完成；订单保留原始/已到货/待到货/拒收数量，防止超量收货 |
| 入库管理 | 五种入库类型（采购/生产/销售退货/调拨/其他）；入库单 → 收货 → 验收 → 质检 → 上架任务 → 上架 → 库存增加 → 库存流水 → 操作日志；支持部分收货与异常收货（少货/多货/错货/破损/包装/批次/效期异常），异常可拍照上传并进入异常中心 |
| 质检 | 免检/抽检/全检；记录检验数量、合格/不合格数量、检验人/时间/原因/图片附件；处理结果：合格/部分合格/不合格/退供应商/报废/返工/降级/转不良品仓/特批放行 |
| 上架 | 待上架 → 上架中 → 已完成；推荐库位 + 手动指定 + 扫码；推荐库位考虑容量、商品已有位置、库区类型、批次、商品属性、拣货需求 |
| 销售管理 | 客户、销售订单（商品/数量/单价/金额/仓库/收货地址/配送方式）；流程：订单 → 审核 → 库存预占 → 出库 |
| 出库 | 五种出库类型（销售/生产领料/调拨/其他/报损）；销售订单 → 库存分配 → 拣货 → 复核 → 打包 → 发货 → 库存正式扣减 |
| 库存分配 | FIFO / FEFO / 指定批次 / 指定仓库 / 指定库位；必须展示分配理由（为什么这个库位/批次、库存是否满足） |
| 拣货 | 单订单/批量/波次/分区拣货；拣货单含 SKU/来源库位/数量/操作人/完成时间；支持扫码、缺货、少货、库位异常、替代处理 |
| 复核 | 重新确认 SKU/条码/数量/批次/序列号/订单；识别错货/少货/多货/批次错误/序列号错误 |
| 打包 | 包裹（包裹编号/包装材料/长宽高/重量/体积/快递/快递单号）；一个订单允许多个包裹 |
| 发货 | 发货单号/物流公司/物流单号/发货仓/发货时间/发货人/包裹数量；状态：待发货/已发货/运输中/已签收/异常 |
| 退货 | 销售退货：申请 → 审核 → 收货 → 质检 → 正常库存/不良品；采购退货：申请 → 审核 → 退货出库 → 供应商 |
| 调拨 | 仓↔仓、库位↔库位；状态：草稿/待审核/待出库/调拨中/待入库/已完成/已取消；源仓减少、目标仓增加，保留完整流水 |
| 盘点 | 全盘/按仓/按库区/按货架/按库位/按 SKU/周期盘点/动碰盘点/抽盘；创建 → 冻结范围 → 实盘 → 差异 → 审核 → 调整 → 库存流水；禁止直接修改系统库存"解决差异" |
| 库存调整 | 申请 → 原因 → 审核 → 执行 → 生成流水；支持盘盈/盘亏/损耗/报废/其他 |
| 异常中心 | 统一处理收货/质检/上架/库存/拣货/复核/物流/盘点/系统异常；生命周期：发现 → 创建 → 分派 → 处理中 → 待复核 → 已解决 → 已关闭；支持图片/附件/评论/处理人/责任人/处理记录 |

## 6. 最终验收场景

系统完成后必须能真实演示以下 7 个场景：

### 场景 1：采购入库

```text
创建供应商 → 创建采购订单 → 审核 → 模拟到货 → 收货 → 质检 → 上架
→ 库存增加 → 查看库存流水 → 打印入库单 → 导出 Excel
```

### 场景 2：销售出库

```text
创建客户 → 创建销售订单 → 审核 → 库存预占 → 生成拣货任务 → 拣货
→ 复核 → 打包 → 发货 → 库存扣减 → 查看物流 → 打印发货单
```

### 场景 3：仓库调拨

```text
A仓 → 调拨申请 → 审核 → A仓出库 → 调拨中 → B仓收货 → B仓入库 → 库存流水
```

### 场景 4：盘点

```text
创建盘点任务 → PDA 扫码 → 实盘 → 系统对比 → 产生差异 → 审核 → 调整库存 → 查看审计日志
```

### 场景 5：Excel

```text
下载模板 → 填 Excel → 上传 → 校验 → 错误提示 → 预览 → 导入 → 查看导入结果 → 导出错误文件
```

### 场景 6：打印

```text
选择 SKU → 选择标签模板 → 打印预览 → 打印
```

### 场景 7：追溯

输入 SKU / 批次 / 序列号 / 单据号，可追踪完整链路：

```text
采购来源 → 入库 → 库位 → 调拨 → 出库 → 客户 → 退货
```

### 场景 8：扫码枪现场验收

环境：一把 USB 扫码枪 + Windows PC + Chrome + StockFlow，现场走通 13 项业务（采购收货/入库/上架/库存查询/拣货/复核/打包/发货/盘点/移库/调拨/退货/序列号追溯），满足 11 条检查项（不依赖鼠标、扫错立即发现、重复扫码不重复业务、扫码异常可手工兜底等）。

完整标准见 [scanner.md §11](scanner.md)。

### 场景 9：工业 PDA 现场验收（StockFlow Scan）

拿一台真实工业扫码终端（Zebra/Honeywell/UROVO 类）安装 StockFlow Scan，连接真实仓库网络，登录后直接完成收货、上架、拣货、复核、盘点、移库、调拨、打包、发货和库存查询，所有库存变化由后端真实业务逻辑完成；覆盖实体 Scan 键、连续扫码、网络断开恢复、切换用户、真实设备测试清单。

完整标准见 [devices.md §17](devices.md)。

## 7. 交付标准

最终交付不是"页面看起来能用了"，而是：

> **前端、后端、数据库、业务流程、库存、权限、Excel、打印、扫码、报表、日志、审计、任务、部署、测试形成完整闭环。**

开发过程中始终站在真实仓库工作人员的角度自检：

```text
仓库管理员真的会这样操作吗？库存会不会错？多人同时操作会不会错？
这个单据以后能不能查？发生异常以后能不能追责？
客户/供应商/仓库数据以后能不能导出？单据以后能不能打印？
月底能不能做报表？换一个操作员还能不能继续工作？
服务器重启后数据会不会丢？这个功能在生产环境是否可维护？
```

---

## 8. 毕业论文支撑点

系统必须具备以下可供论文分析的真实内容：

```text
需求分析、系统架构、数据库设计、权限设计、库存算法、业务流程
系统安全、并发控制、Excel 导入导出、条码管理、打印系统
数据可视化、测试、性能优化
```

系统必须有足够真实的业务逻辑（库存状态机、并发控制、FEFO 分配、审批链、审计链等）支撑论文的算法与设计分析章节，不能只是"用了某技术栈，写了几个页面"。

## 9. 演示数据要求

开发环境提供演示数据：商品、SKU、仓库、库位、供应商、客户、采购订单、入库单、库存、销售订单、出库单、调拨、盘点。

**硬性要求**：演示数据必须与生产初始化逻辑完全分离（详见 [deployment.md §6](deployment.md)）。

## 10. 禁止假功能清单

以下情况一律禁止：

```text
按钮点击后只弹 Toast
页面有数据但是数据库没有数据
Excel 按钮实际上下载静态文件
打印按钮实际上调用 window.print 且没有打印模板
库存数字前端自己计算
审批状态前端直接修改
权限只控制菜单
Dashboard 数据写死
报表使用假数据
PDA 只是把 PC 页面缩小
```
