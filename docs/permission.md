## 2. 权限模型（RBAC + 数据权限）

**核心要求：角色不能只是前端隐藏菜单。**

权限必须真正控制以下六个层面：

```text
1. 页面权限    路由级，无权限页面不可达
2. 按钮权限    操作级，无权限按钮不渲染/禁用
3. API 权限    接口级，后端中间件强制校验
4. 数据权限    行级，仓库/部门/本人过滤
5. 仓库权限    仓库维度数据隔离
6. 部门权限    部门维度数据隔离
7. 操作权限    敏感操作单独授权（审批、调整库存、导出等）
```

权限模型：`用户 → 角色 → 权限点`；权限点覆盖菜单、按钮、API 三级；用户可归属部门，可绑定仓库范围。

## 3. 登录与认证

### 3.1 认证机制

```text
用户名密码登录
JWT / Token
Refresh Token
Token 过期与刷新
强制退出（管理员可踢下线）
```

### 3.2 登录保护

```text
登录失败次数限制（连续失败 N 次锁定）
账户锁定与解锁
初始密码强制修改
强密码策略
密码修改
```

### 3.3 登录记录

每次登录记录：

```text
登录日志、IP、User-Agent、登录设备
最后登录时间
```

### 3.4 在线会话管理

后台可查看：

```text
当前在线用户、登录设备、登录 IP、登录时间、最近活动
```

支持管理员**强制下线**（踢出会话，Token 立即失效）。

## 4. 数据权限

除 RBAC 外，必须支持数据权限范围：

```text
全部仓库
指定仓库
指定部门
本人
本人负责
```

典型场景：

```text
A 仓管理员 → 只能看到 A 仓库存与单据
总部管理员 → 可以看到所有仓库
```

实现位置：数据查询统一在 Service/Repository 层注入数据权限过滤条件，禁止前端传参决定数据范围。

---

## 5. 前端权限接入约定

1. 路由守卫：根据用户权限点动态注册/拦截路由。
2. 按钮级控制：权限指令/组件（如 `v-permission`），无权限不渲染。
3. 请求层：Token 过期自动刷新或跳转登录；403 统一提示无权限。
4. 前端权限仅是体验优化，**一切以后端校验为准**。

---

## 6. 敏感操作与审计联动

以下操作需要额外权限点，并强制记录审计日志（architecture.md §8）：

```text
库存调整执行、审批通过/驳回、用户与角色变更
权限变更、系统配置修改、数据导出、强制下线
```
