## 2. 开工前项目分析（阶段 1 强制产出）

开始修改代码前，必须分析当前仓库并输出：

```text
1. 当前项目结构
2. 当前技术栈
3. 已实现功能
4. 缺少功能
5. 数据库现状
6. 后端现状
7. 前端现状
8. 可以复用的模块
9. 需要重构的模块
10. 数据模型问题
11. 权限问题
12. 库存一致性问题
13. 生产环境风险
14. 推荐开发顺序
```

分析结论写入 `docs/plans/`（或本目录对应文档）后再开始实施。

## 3. 每阶段完成标准（Definition of Done）

每完成一个模块，必须同时完成以下九项，缺一不可：

```text
数据库    Migration + 索引
后端      Service/Repository 完整实现
API      接口 + 文档 + 校验
前端      页面 + 交互 + 状态反馈
权限      权限点接入（页面/按钮/API/数据）
校验      后端完整校验
错误处理  统一错误码 + 用户可读信息
日志      操作日志 + 关键审计
测试      单元/集成测试通过
```

**禁止**：先做一堆前端页面，最后再补后端。

---

## 4. 长任务执行约定

- 中大型任务建立任务状态文档（TASK_STATE），按阶段拆分，先读后改。
- 单一真相来源：业务规则以 docs/ 为准，禁止并行造第二套实现。
- 最小修改原则：不擅自扩大范围；重构必须保留有效业务能力。
- 每步实际验证后推进；中断后从任务状态恢复，不重头再来。

## 5. 里程碑与验收

- **里程碑 M1**（阶段 1–8）：基础平台 + 库存核心可用，库存恒等式与并发测试通过。
- **里程碑 M2**（阶段 9–13）：业务闭环可用，requirements.md 场景 1–4、7 可演示。
- **里程碑 M3**（阶段 14–19）：平台能力完整（Excel/打印/扫码枪/设备管理），场景 5、6、8 可演示，扫码第一优先级场景（收货/上架/拣货/复核/盘点/移库）与 StockFlow Scan 真机验收（场景 9）可用，监控备份就绪。
- **里程碑 M4**（阶段 20–22）：全部测试通过、性能达标、生产部署完成，7 个验收场景全部走通（requirements.md §6）。
