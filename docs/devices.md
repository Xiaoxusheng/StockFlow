## 1. 多终端产品结构

StockFlow 最终由三端组成：

```text
StockFlow
│
├── Web    PC 企业管理端（React + Ant Design）
├── Pad    平板仓储作业端（仓库主管/盘点/查询）
└── Scan   Android 工业扫码终端（StockFlow Scan 独立应用）
```

外部扫码设备：

```text
扫码设备
├── USB HID 扫码枪
├── Bluetooth HID 扫码枪
├── Zebra 内置扫描引擎
├── Honeywell 内置扫描引擎
├── UROVO 内置扫描引擎
└── 摄像头扫码
```

总架构：

```text
PC 管理端 + Pad 仓储作业端 + StockFlow Scan 工业扫码端
+ USB / Bluetooth 扫码枪 + 工业 PDA 内置扫描头
    ↓
统一 StockFlow Backend
    ↓
统一库存 / 订单 / 任务 / 审计数据
```

**硬性规则**：绝对不能出现"Scan 一套库存、Pad 一套库存、PC 一套库存"。三端只能通过：

```text
PC / Pad / Scan → 统一 API → 统一业务服务 → 统一数据库
```

库存变更只发生在后端业务服务（见 §10）。

## 2. 真实设备设计原则

目标设备不是普通手机，而是真实仓储现场设备：

```text
工业 Android PDA
仓储手持终端
带实体扫描按键的手持机
固定工作站扫码枪
```

典型设备类别（作为适配参考，不锁定品牌）：

```text
Zebra TC22 / TC27       工业 Android 手持终端
Honeywell CT30 XP       工业 Android 手持终端
UROVO DT50              工业 Android 手持终端
```

**禁止把实现写死到某一家厂商**，必须建立 Scanner Adapter Layer（§4、§5），不同厂商设备通过统一接口接入。

**Scan 不是 PC Web 缩小版**：禁止把 PC Sidebar + PC Table + PC Dashboard 直接缩小到 PDA。StockFlow Scan 必须围绕：

```text
任务驱动、扫码驱动、触摸驱动
低输入、少点击、快速反馈、高可靠性
```

## 3. StockFlow Scan 独立应用

### 3.1 定位与技术方案

新增正式应用 **StockFlow Scan**：

> 面向仓库一线员工的工业扫码作业系统。不是后台管理系统，也不是简单 H5 页面。

技术方案（结合团队技术栈与维护成本选择）：

| 方案 | 说明 | 定位 |
|---|---|---|
| **React Native**（推荐） | TypeScript 与 Web 端复用业务逻辑与类型；通过原生模块桥接厂商扫描 SDK 与实体 Scan 键 | 主选 |
| Capacitor（WebView 容器） | Web 代码复用度最高，DataWedge 等通过广播/插件桥接 | 轻量备选 |
| Kotlin 原生 | 性能与设备能力最直接 | 团队具备 Android 能力时 |

无论哪种方案，必须能够**直接访问 Android 扫描能力、设备能力和实体 Scan 键**。

### 3.2 首页

│ A仓      ● 在线      张三│

首页必须显示：当前用户、当前仓库、网络状态、扫码设备状态、App 版本、待办任务、异常任务。

## 4. Scanner 抽象层（Scan 端）

### 4.1 模块结构

```text
scanner/
├── ScannerManager        设备生命周期与状态
├── ScannerService        业务唯一入口
├── ScannerAdapter        适配器接口
├── ScanResult            统一结果
├── ScannerProfile        设备扫描配置
│
├── HIDScannerAdapter         USB/蓝牙 HID（PC + Pad）
├── ZebraDataWedgeAdapter     Zebra DataWedge
├── HoneywellScannerAdapter   Honeywell
├── UrovoScannerAdapter       UROVO
└── CameraScannerAdapter      摄像头（备用）
```

### 4.2 强制约束

业务页面**禁止**：

```text
监听键盘
调用厂商 SDK
操作 DataWedge
操作串口
```

业务页面只能使用 ScannerService：

```ts
scannerService.startScan()
scannerService.stopScan()
scannerService.onScan(...)
```

### 4.3 统一 ScanResult

```ts
interface ScanResult {
  rawCode: string
  source: 'hid' | 'zebra' | 'honeywell' | 'urovo' | 'camera' | 'serial'
  timestamp: number
  symbology?: string   // Code128 / QR / ...
}
```

业务层不能关心具体硬件品牌（与 scanner.md §3.1 为同一契约）。

### 4.4 实体 Scan 按键

必须支持工业 PDA 实体 Scan 键（左侧/右侧/中间，不同厂商位置不同）。Adapter 层统一成：

```text
onScanTrigger()
```

业务页面不关心按的是哪个物理按键。

### 4.5 生命周期处理

Adapter 必须处理以下场景，**不能假设 App 永远处于前台**：

```text
应用启动、前台切换、扫码、页面切换、重新绑定、异常恢复
```

## 5. 厂商适配器

### 5.1 Zebra（DataWedge）

StockFlow Scan 需要：

```text
初始化 Scanner Profile
注册扫码接收
接收扫描结果 → 转成统一 ScanResult
```

### 5.2 Honeywell

HoneywellScannerAdapter 统一处理：

```text
Scanner 初始化、Scanner 状态、Scan 事件、异常、释放、重新连接
```

### 5.3 UROVO

UrovoScannerAdapter 统一处理：

```text
Scanner 初始化、实体 Scan 键、扫描结果、声音、震动、Scanner 状态
```

### 5.4 摄像头

没有专业扫码设备时提供 Camera Scanner：打开摄像头 → 扫二维码/条码 → 解析 → 统一 ScanResult。摄像头扫码为**备用方式**，高频仓储作业优先使用专业扫描头。

### 5.5 HID（PC 固定工作站 + 蓝牙）

USB HID / Bluetooth HID 的接入与识别规则见 scanner.md §2；Pad 端通过蓝牙 HID 扫码枪接入，原则与 HID 一致，必须同时支持手工输入 + 扫码输入。

## 6. 设备生命周期管理

### 6.1 设备注册

StockFlow Scan 首次安装运行时进行设备注册，输入：

```text
设备编码 + 服务器地址
```

或**扫码激活二维码**（推荐，见 §6.2）。

### 6.2 设备激活（二维码）

后台路径：`系统管理 → 设备管理 → 新建设备 → 生成激活二维码`。

Scan 端：首次启动 → 扫描激活二维码 → 激活设备 → 自动获取并完成：

```text
服务器地址、设备编号、仓库、初始配置
```

避免人工输入服务器地址，支持批量部署（配置二维码见 §7.5）。

### 6.3 设备绑定仓库

设备（如 `SF-SCAN-001`）绑定仓库（如 A仓）。员工登录后当前仓库自动取设备绑定仓库：

```text
普通员工不能任意切换到其他仓库
拥有权限的管理员/主管可以切换
```

### 6.4 共享设备

仓库 PDA 经常多人使用，必须支持：

```text
员工 A → 登录 → 完成任务 → 锁屏
员工 B → 解锁 → 登录
```

或快速切换用户。**硬性规则**：所有业务操作必须记录真实操作者，禁止所有人共用一个普通账号。

### 6.5 自动锁屏

可配置：1分钟 / 5分钟 / 10分钟 / 30分钟 / 关闭。超时后锁定当前设备，恢复需要身份验证。

## 7. 设备管理后台（PC 管理端）

### 7.1 设备管理页面

`系统管理 → 设备管理`，展示字段：

```text
设备编号、设备名称、设备类型、品牌、型号、系统
App 版本、当前用户、所属仓库
状态、最后在线、最后扫码时间
```

支持操作：

```text
绑定设备、解绑设备、停用设备、远程注销
查看设备日志、查看扫码日志
```

### 7.2 设备健康监控

PC 后台增加**设备监控**：

```text
设备在线、网络、电量（设备支持时）
App 版本、最后扫码、最近错误、最后同步
```

### 7.3 配置下发

PC 管理端可下发：

```text
扫码模式、声音、震动、自动聚焦、连续扫码
扫码超时、默认仓库、任务刷新间隔、自动锁屏
```

Scan 启动后自动同步配置。

### 7.4 App 更新

设备后台展示 App 版本 / 最新版本。**架构预留**：APK 升级、版本检查、强制升级、灰度升级。不要求一开始实现复杂 OTA，但接口与数据结构必须留出来（app_versions）。

### 7.5 设备配置二维码

管理员在 PC：`设备管理 → 选择设备 → 生成配置二维码`；Scan 端扫描后自动导入服务器地址、设备编号并自动绑定，方便批量部署。

## 8. 网络与离线容错

### 8.1 网络状态展示

Scan 端顶部固定显示：

```text
● 在线    ⚠ 网络不稳定    × 离线
最后同步：15:32:21
```

### 8.2 离线缓存

支持：任务缓存、页面缓存、草稿缓存、用户配置缓存。

### 8.3 断网行为（硬性规则）

网络断开时：

```text
明确告知用户
保留当前输入
禁止假装业务成功
```

对于**最终库存变更类操作**（出库、发货、库存调整等），必须得到服务器确认才允许置为成功；**禁止离线状态偷偷修改最终库存**。

### 8.4 网络恢复与冲突处理

```text
Offline → Online → 同步 → 服务器校验 → 显示结果
```

数据冲突（库存已变化、任务已被其他人领取、订单状态已变化）必须明确提示，并让员工重新确认后再提交。

## 9. Scan 端交互规范

### 9.1 扫码状态

扫码端顶部始终显示扫描状态：

```text
扫描 ●   已连接 / 未连接 / 初始化中 / 异常
```

### 9.2 声音与震动

```text
成功 → 短 Beep + 短震
错误 → 错误提示音 + 长震
```

系统设置支持声音开/关、震动开/关（设备支持时；详见 scanner.md §6.2）。

### 9.3 错误反馈

所有错误必须清晰，禁止只显示"操作失败"，格式示例（错误码体系见 scanner.md §6.1）：

```text
❌ 商品不匹配

当前任务：SKU001234
扫描：SKU009999
请扫描正确商品。
```

```text
❌ 库位错误

任务要求：A-01-03-05
当前扫描：A-01-03-08
```

### 9.4 成功反馈与自动聚焦

```text
✓ 扫描成功

SKU001234
+1

已完成：18 / 20
```

成功后自动聚焦下一次扫码。

### 9.5 连续扫码模式

支持：单次模式、连续模式、自动下一项。

```text
扫描 → +1 → 震动 → Beep → 自动等待下一次
```

员工整个高频作业过程不需要鼠标。

### 9.6 任务上下文扫码（重点）

进入业务任务后，系统知道当前任务的期望对象与顺序（如拣货：库位 → 商品 → 数量）。员工扫描后直接按任务上下文验证：

```text
扫描库位 → 直接验证当前任务库位
扫描 SKU → 直接验证当前任务 SKU
```

**禁止**让员工每次扫码后再选择"这是商品 / 这是库位 / 这是任务"。

### 9.7 手工输入兜底

任何扫码业务都可以扫码 + 手工输入，手工输入必须经过完全一样的业务校验，不能绕过库存安全（scanner.md §4.7）。

### 9.8 扫码历史

Scan 端提供"最近扫码"：

```text
15:20:01  SKU001      ✓
15:20:03  A-01-03-05  ✓
15:20:05  SKU999      ✕
```

字段：时间、条码、识别对象、任务、结果。

## 10. 库存安全（Scan 端硬性规则）

### 10.1 库存必须由后端控制

```text
扫码端：扫描 → 请求 API
后台：  权限校验 → 状态校验 → 库存校验 → 事务 → 幂等 → 并发控制
然后：  执行库存变化
```

扫码端禁止本地计算或修改库存（inventory-rules.md §1）。

### 10.2 高风险操作

以下操作不能只依靠扫码自动提交，必须：扫码 → 校验 → **明确确认** → 服务端执行：

```text
库存调整、报损、强制出库、库存覆盖、盘点差异确认、发货完成
```

（风险分级体系见 scanner.md §6.4–6.5。）

### 10.3 盘点差异

盘点扫码累计差异后（如系统 100、实盘 98、差异 −2）：

```text
不能直接改库存
差异 → 原因 → 提交 → 审核 → 调整库存 → 库存流水
```

支持**盘点快照**与动态盘点：盘点过程中发生出库/入库/移库/调拨变化时，必须正确处理最终差异（以快照时点与业务流水推导，见 business-flow.md §10.2）。

## 11. Scan 端业务场景

收货、质检、上架、拣货、复核、打包、发货、盘点、移库、调拨、退货的扫码流程与校验规则以 [scanner.md §7](scanner.md) 为准，Scan 端在此基础上保证：

- 界面显示任务关键数量：订单数量、已收数量、待收数量、本次数量（收货）等。
- 支持缺货、少货、库位异常、商品异常的上报入口。
- 扫码查库存/库位/批次/序列号、箱码、托盘码入口见菜单（§3.3），展示内容与 scanner.md §7.13–7.16 一致。

**打印联动**：扫码端完成业务后可直接打印（通过打印中心模板与任务，printing.md）：

```text
商品标签、箱码、托盘码、库位标签、入库单、出库单、发货凭证
```

例如：收货 → 质检 → 上架 → 打印标签；打包 → 生成箱码 → 打印箱码。

## 17. 测试与验收

### 17.1 真实设备测试（强制）

**不能只使用浏览器开发者工具模拟手机尺寸**。测试至少覆盖：

```text
PC + USB HID 扫码枪
Android Pad + Bluetooth HID 扫码枪
工业 Android PDA + 内置扫描头
```

并验证：扫码、连续扫码、实体 Scan 键、声音、震动、网络断开、网络恢复、登录、切换用户、任务、库存、盘点、打印、异常。

### 17.2 扫码业务验收链路

```text
采购收货 → 扫码商品 → 库存进入待检 → 质检 → 上架 → 库存增加

销售订单 → 库存锁定 → 扫码拣货 → 扫码复核 → 打包
→ 扫描箱码 → 发货 → 库存扣减

盘点 → 扫码库位 → 连续扫码 → 生成差异 → 审核
→ 库存调整 → 库存流水
```

### 17.3 最终体验标准

员工拿到工业 PDA 后：

```text
开机 → StockFlow Scan → 登录 → 自动进入所属仓库 → 看到待办任务
→ 按实体 Scan 键 → 扫描 → 系统自动识别 → 自动校验 → 成功反馈 → 自动下一步
```

整个高频作业过程：

```text
尽量不输入、尽量不点鼠标、尽量不切换页面、尽量不重复确认
```

但高风险库存动作仍然必须明确确认（§10.2）。

### 17.4 最终验收标准

> 拿一台真实工业扫码终端安装 StockFlow Scan，连接真实仓库网络，登录后能够直接完成收货、上架、拣货、复核、盘点、移库、调拨、打包、发货和库存查询，并且所有库存变化都由后端真实业务逻辑完成。
